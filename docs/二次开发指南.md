# 离线二次开发指南

> 本文件随离线部署包发布（包内 `docs/二次开发指南.md`，并复制一份到包根 `README-二次开发.md`）。
> 适用场景：内网（无外网）机器上需要**修改 mcp-dbtools 源码**、跑测试、调试，但无法访问 PyPI。

## 一、离线包内的可开发资源

| 路径 | 说明 |
| --- | --- |
| `source/` | **完整项目源码快照**（`src/`、`tests/`、`scripts/`、`deploy/`、`docker/`、`docs/`、`pyproject.toml`、`requirements*.txt`、`.env.example` 等），构建机执行 `git archive HEAD` 生成 |
| `offline_packages_win/`（Linux 包为 `wheels/`） | 运行时依赖 + **开发依赖**（`pytest` / `pytest-asyncio` / `httpx`）+ 构建后端（`setuptools` / `wheel`）的离线 wheel |
| `dist/` | 生产部署用的项目 wheel（`install_offline.bat` / `install.sh` 使用） |
| `drivers/` | JDBC 驱动 jar（DB2 的 `db2jcc4.jar`、MySQL 的 `mysql-connector-j-*.jar` 需自行放入） |
| `config/` | 数据源配置示例 |

注意事项：

- `source/` **不含 `.git` 历史**。需要版本管理请自行初始化：`git init && git add -A && git commit -m "import"`。
- 快照只包含**已提交到 git** 的内容；构建时若工作区有未提交改动，构建脚本会打印 `[WARN]`。
- 内网没有 PyPI，**新增或升级依赖必须在外网重新构建离线包**后再带入内网。

## 二、Windows：搭建离线开发环境

以离线包解压在 `D:\mcp-dbtools` 为例（Windows 包是平铺结构，解压目录即生产安装目录）：

```bat
cd /d D:\mcp-dbtools\source

:: 1. 建独立开发虚拟环境（与生产的 D:\mcp-dbtools\.venv 互不影响）
python -m venv .venv

:: 2. 离线可编辑安装本项目（-e：改 src\ 下的代码立即生效，无需重装）
.venv\Scripts\pip install --no-index --find-links=..\offline_packages_win -e .

:: 3. 安装开发 / 测试依赖
.venv\Scripts\pip install --no-index --find-links=..\offline_packages_win -r requirements-dev.txt

:: 4. 跑测试（缺少数据库 / JDBC 驱动的集成测试会自动 skip，不算失败）
.venv\Scripts\python -m pytest -q

:: 5. 用源码方式启动服务调试
set MCP_DBTOOLS_DRIVERS_DIR=..\drivers
set MCP_DBTOOLS_CONFIG=%CD%\config\datasources.json
.venv\Scripts\python -m mcp_dbtools --transport streamable-http
```

## 三、Linux：搭建离线开发环境

```bash
cd /opt/mcp-dbtools/source

python3 -m venv .venv
.venv/bin/pip install --no-index --find-links=../wheels -e .
.venv/bin/pip install --no-index --find-links=../wheels -r requirements-dev.txt
.venv/bin/python -m pytest -q

MCP_DBTOOLS_DRIVERS_DIR=../drivers \
MCP_DBTOOLS_CONFIG=$PWD/config/datasources.json \
  .venv/bin/python -m mcp_dbtools --transport streamable-http
```

## 四、常见问题

| 现象 | 处理 |
| --- | --- |
| `pip install -e .` 报找不到 `setuptools` | 离线 wheel 目录已含 `setuptools` / `wheel`，确认 `--find-links` 指向正确；仍报错可加 `--no-build-isolation`，并先执行 `pip install --no-index --find-links=<包内 wheel 目录> setuptools wheel` |
| 改了代码，pm2 里的服务没变化 | pm2 跑的是**生产 venv**（`..\.venv`，非 editable）。要么按上面第 5 步用源码方式启动，要么在生产 venv 里也做一次 `pip install --no-index --find-links=..\offline_packages_win -e ..\source` |
| 测试报 `{ENC:...}` 解密失败 | 设置 `MCP_DBTOOLS_SECRET_KEY`（必须与加密时使用的密钥一致），或把 `source/config/datasources.json` 里的密码改成 `{ENV:变量名}` 引用 |
| 报驱动类找不到 | 把 jar 放进 `drivers\`，并设置 `MCP_DBTOOLS_DRIVERS_DIR` 指向该目录 |
| 需要新增第三方依赖 | 外网构建机改 `requirements.txt` 后重新执行 `bash scripts/build_offline.sh --platform windows`，把新包带入内网（内网无法 `pip install` 联网包） |
| 升级离线包后源码被改动的地方会丢吗 | 升级脚本会先把旧的 `source/` 整个备份到 `backup-时间戳/source`（Windows 为 `backup-时间戳\source`），再用新版快照覆盖。**建议有实质改动时先用 git 管理或另存备份** |
